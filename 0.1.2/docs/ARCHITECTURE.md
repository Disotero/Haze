# Как устроен Haze

Короткая карта кода для тех, кто полезет внутрь. Код писался итеративно в паре с ИИ, поэтому местами он «вырос», а не спроектирован, — но структура ниже держится.

## Общая схема

Haze — Electron-приложение из нескольких прозрачных окон без рамок. Каждое окно — отдельная HTML-страница в `src/renderer/`, а вся работа с Windows идёт из главного процесса `src/main/`.

```
            ┌──────────────── главный процесс (src/main) ────────────────┐
            │ main.js — окна, трей, IPC, настройки, правила «кто кого    │
            │           перекрывает», полноэкранные игры                 │
            │ desktop.js ── koffi → user32/dwmapi/shell32 (WinAPI)       │
            │ psbridge.js ── помощники haze-sys.exe (Rust) / .ps1        │
            └───────────────▲───────────────────────────▲────────────────┘
                            │ IPC через preload.js       │
  ┌───────────┬─────────────┼─────────┬─────────────┬───┴──────┬──────────┐
  wallpaper   widgets       topbar    dock          settings   browser
  (под        (на уровне    (app bar  (низ экрана,  (окно      (окно для
  иконками)   рабочего      на краю   авто-скрытие) настроек)  сайтов из
              стола)        экрана)                            лаунчеров)
```

## Главный процесс — `src/main/`

| Файл | Что делает |
|---|---|
| `main.js` | Точка входа: создаёт окна, трей, IPC-обработчики, применяет настройки, дважды в секунду проверяет, не закрыт ли экран развёрнутым/полноэкранным окном (пауза обоев, прятанье панели и дока). Единственный экземпляр; `--quit` просит запущенную копию закрыться. |
| `settings.js` | Настройки в `%APPDATA%\Haze\settings.json`. `DEFAULTS` — полный список ключей; сохранённое мёржится поверх, так что новые ключи появляются сами. |
| `desktop.js` | Единый вход ко всему WinAPI (через [koffi](https://koffi.dev/)); сама работа разложена по модулям ниже. |
| `win32.js` | Объявления функций user32/dwmapi/kernel32/gdi32/shell32, константы и общие помощники (HWND окна, путь процесса). |
| `wallpaper.js` | Встраивание окна обоев в `WorkerW`/`Progman`, иконки рабочего стола. |
| `windows.js` | Порядок слоёв Haze, список окон для дока, окно на переднем плане, фокус, форма окон, хуки событий окон. |
| `appbar.js` | App bar панели и панель задач Windows (автоскрытие, скрытие, «подглядывание»). |
| `input.js` | Раскладка клавиатуры и виртуальные рабочие столы. |
| `power.js` | Батарея, сон, «Не беспокоить». |
| `runtool.js` | Запуск системных утилит (reg, shutdown, taskkill, PowerShell…) по полному пути, с таймаутом и обработкой ошибок. |
| `poller.js` | Все периодические опросы; «Слабый ПК» растягивает их на лету. |
| `topbar.js` | Регистрирует панель как app bar (резервирует полосу экрана, как панель задач). |
| `dock.js` | Окно дока у любого края экрана, автоскрытие, запущенные приложения, программы из трея. |
| `psbridge.js` | Запускает долгоживущего помощника: JSON-строки на stdout, команды на stdin. Если рядом есть `haze-sys.exe`, для status/media запускается он, иначе — `.ps1`; помощник, который трижды подряд падает молча, заменяется скриптом. |
| `status.ps1` | Громкость (Core Audio), сеть, Bluetooth, микрофон/камера. Команды `mute`, `vol N`, `volstep ±N`, `net 0/1`, `slow 0/1`. Запасной вариант для `haze-sys.exe status`. |
| `media.ps1` / `media.js` | «Сейчас играет» через Windows SMTC и кнопки плеера. Запасной вариант для `haze-sys.exe media`. |
| `tray.ps1` | Какие программы сейчас живут в системном трее. |
| `phone.ps1` | Данные для виджета телефона (USB/MTP, заряд Bluetooth-устройств). |
| `system.js` | CPU / RAM / диск / батарея. |
| `weather.js` | Погода из Open-Meteo (без ключа). |
| `feeds.js`, `hltv.js` | Данные инфо-виджетов: киберспорт (Liquipedia, HLTV, VLR), акции, спорт, новости. HLTV за Cloudflare, поэтому грузится в скрытом окне Chromium. |
| `clockwork.js` | Будильники и таймер выключения — в главном процессе, чтобы работали при любом состоянии окон. |
| `wallpaperengine.js` | Дружба с Wallpaper Engine: находит его через Steam и управляет через `-control`. |
| `browser.js` | Окно-браузер в стиле Haze для сайтов из панелей быстрого запуска. |
| `appicons.js` | Иконки программ и цели ярлыков для дока и лаунчеров. |

## Окна — `src/renderer/`

| Папка | Окно |
|---|---|
| `wallpaper/` | Живой фон: шейдер, видео, картинка. |
| `widgets/` | Все виджеты в одном прозрачном окне. `widgets.js` — сборка, раскладка и проводка; `basic.js` — встроенные виджеты (профиль, часы, плеер, погода, метрики); `extra.js` (время и задачи) и `tools.js` (сеть, цитата, фото, поиск, конвертер); `feedwidgets.js` и `news.js` — инфо-виджеты; `drag.js` — перетаскивание, грипы и масштаб, `hit.js` — хит-тест кликов, `clip.js` — клип «живого стекла», `panel.js` — дневная панель, `ring.js` — карточка будильника, `widgetmenu.js` — контекстное меню; `layout.js` — геометрия раскладки; остальные файлы — отдельные виджеты и иконки. |
| `glass/` | Вспомогательное окно для «живого стекла» поверх Wallpaper Engine. |
| `topbar/` | Информационная панель. |
| `dock/` | Док. |
| `settings/` | Окно настроек. |
| `welcome/` | Окно знакомства при первом запуске (первый запуск = ещё нет `settings.json`). |
| `browser/` | Панель инструментов встроенного браузера. |
| `shared/` | Тема и палитры (`theme.css/js`), пресеты раскладок, список городов, сайты погоды, общие помощники (`util.js`: загрузка с повтором, безопасный `url()`; `clip.js`: форма стекла). |

`src/preload.js` — единственный мост: выставляет в окна объект `window.cozy` с методами (`getSettings`, `statusCommand`, `openSettings`, …). Имя `cozy` осталось от прежнего названия проекта «Cozy Desktop».

## Отладка

- Ошибки главного процесса пишутся в `%APPDATA%\Haze\errors.log` (не больше ~1 МБ, старый уходит в `errors.log.1`).
- `npm run lint` — ESLint, `npm test` — тесты `node --test` (настройки, помощники). Оба запускаются и в GitHub Actions.
- `HAZE_PROF=1` — раз в 30 секунд пишет в консоль, сколько времени занимает каждый опрос.
- Переменная окружения `COZY_CAPTURE=<папка>` — через 8 секунд после старта Haze сохранит PNG каждого слоя (обои, виджеты, панель, док). Удобно проверять вёрстку без скриншотов экрана.
- Перезапуск из исходников: `npm run stop`, потом `npm start`. Не убивайте процесс принудительно — app bar и скрытая панель задач останутся «висеть». Если всё же убили — следующий запуск Haze сам вернёт панель задач и иконки, или запустите `scripts\restore.cmd`.

## Первый запуск

`settings.isFirstRun()` — нет файла настроек. Тогда `main.js → firstRun()`: если работает Wallpaper Engine, обои переключаются на него; настройки сохраняются (чтобы знакомство было один раз) и открывается окно `welcome/`.

## Сборка

`npm run dist` → `dist\Haze.exe` (electron-builder, цель `portable`). То же самое на GitHub делает `.github/workflows/build.yml`. `asar` выключен намеренно: PowerShell-скрипты из `src/main` запускаются внешним `powershell.exe`, и им нужны настоящие файлы на диске. Конфиг — секция `build` в `package.json`.

### Нативный помощник `native/haze-sys`

Крейт на Rust (`windows-rs`), один бинарник с двумя режимами: `haze-sys.exe status` и `haze-sys.exe media` заменяют `status.ps1` и `media.ps1` с тем же протоколом (те же JSON-ключи и команды). Изменения приходят событиями Windows (Core Audio, IP Helper, WinRT Radios и SMTC), а не опросом раз в секунду; два процесса занимают ~2–3 МБ вместо ~170 МБ у PowerShell.

Сборка: `cargo build --release` в `native/haze-sys` (подойдёт тулчейн MSVC или GNU; у GNU путь к тулчейну не должен содержать кириллицу). `npm run dist` кладёт `target/release/haze-sys.exe` в ресурсы exe (`build.extraResources`), а в режиме разработки `psbridge.js` берёт его прямо из `target/release`. Без собранного помощника всё работает на `.ps1`. Тесты: `cargo test`.
